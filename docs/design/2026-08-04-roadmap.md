### 換機器接續開發前必看：環境需求

Phase 0 踩了不少建置環境的坑，換一台新機器前務必確認：

1. **必須裝完整 Xcode.app**（不是只有 Command Line Tools）— MLX Swift 需要 `xcrun metal` 編譯自訂 Metal shader，這個工具只隨完整 Xcode 附帶。目前用的是 Xcode 16.4，相容 macOS 14.5+，不需要升級到 macOS 26 Tahoe。
2. **MLX 相關程式碼必須用 `xcodebuild` 建置，不能用 `swift build`**：純 SPM 建置雖然會成功，但執行時會噴 `Failed to load the default metallib`（Metal shader 封裝是 Xcode build phase，不是 SPM plugin）。WhisperKit 那邊沒有這個限制，純 `swift build` 就能跑。
3. 對本機 `Package.swift` 資料夾直接下 `xcodebuild -scheme <package-name> -configuration Release -destination "platform=macOS,arch=arm64" -derivedDataPath .build/xcode -skipMacroValidation build` 即可，Xcode 16 會自動抓套件名稱當 scheme，不需要另外建 `.xcodeproj`。
4. `@main` 進入點檔案**不能命名為 `main.swift`**（`xcodebuild` 會報 `'main' attribute cannot be used in a module that contains top-level code`，`swift build` 反而不會報這個錯——兩者對這個組合的容許度不同）。
5. 模型下載快取位置：WhisperKit 用 `~/Documents/huggingface/`，MLX/Gemma 4 用 `~/.cache/huggingface/`（兩者路徑不同，不是同一個快取）。換機器要重新下載，Gemma 4 E2B 3.3GB + WhisperKit small ~465MB，抓好時間與網路。
6. 詳細除錯過程與踩坑細節都記在 [2026-08-05 翻譯 spike 結果文件](2026-08-05-phase0-spike-results-translation.md) 的「環境發現」章節。

## 里程碑判斷準則

每個 Phase 完成的定義是「可以實際操作看到功能運作」，不是程式碼寫完但沒驗證。沿用原專案的驗證方式（專案沒有 XCTest，靠手動跑情境）：至少要跑過一次「正常流程」「邊界情況（極短會議）」「錯誤情況（模型載入失敗／記憶體不足）」三種情境，且錯誤情況不能讓 App crash 或遺失已完成的逐字稿。
